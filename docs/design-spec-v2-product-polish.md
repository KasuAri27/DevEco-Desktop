# DevEco Agent Desktop · 设计规格 v2：从「能用」到「像产品」

> 前置：v1（`design-spec-theme-and-typography.md`）已落地——令牌、字号、双色相×双明暗均已验收，**不要回头改**。
> 本文档是设计规格，不含完整实现代码。实现方按文中的结构、状态、文案与验收标准自行落地；视觉参考见 `design-preview/index.html`。
> 写给 Luna 的一句话：v1 你把"有"做对了，v2 要的是"好看"和"懂行"。别急着堆功能，先把质感做出来。

---

## 0. 总原则（先读这一节）

1. **界面不讲实现。** 用户看不到 IPC、配置文件、"暂存于页面运行期间"、"已从桌面配置读取"这类措辞。状态只讲结果："已应用"，或者什么都不说。
2. **选择用可视化，不用表单。** 能让用户"看见再选"的，一律不用 `<select>`。
3. **所有颜色来自令牌**（v1 的验收标准继续生效）。新增组件一律不得出现字面色值。
4. **动效有章法**：新增 3 个动效令牌（见 §8），任何过渡都从中取值，并尊重 `prefers-reduced-motion`。
5. **每个新组件必须交付 4 种外观下的表现**（战狼红/冷锋蓝 × 浅/深），验收时逐一截图。

## 1. 外观页重设计（本轮重点）

### 1.1 现状问题
两个下拉框 + 一行状态文字，像后台配置表单。用户选"战狼红"之前根本不知道它长什么样。

### 1.2 新结构

页面分三块，自上而下：

**A. 主题色卡（2 张并排大卡片，替代「主题色相」下拉）**

- 每张卡片是一个**迷你应用窗口缩略图**：左侧细栏 + 顶栏 + 一条用户气泡 + 一条 Agent 回复 + 底部输入框，全部用该卡片自己的色相令牌绘制，用户一眼看到真实效果。
- 缩略图下方：主题名（战狼红 / 冷锋蓝）+ 一行气质描述（例：战狼红「锋利、醒目」；冷锋蓝「冷静、专注」。文案可微调，但必须是气质词，不得是技术词）。
- 选中态：2px `--accent` 描边 + 右上角圆形对勾徽标；未选中 hover 时轻微上浮（用动效令牌）。
- **缩略图必须随当前明暗模式变化**（用户选了深色，两张卡片都预览深色版本），所以"选色相"和"选明暗"在视觉上是联动的。
- 技术约束：令牌目前挂在 `body[data-hue][data-mode]` 上，卡片内要预览"另一套色相"，需要让令牌选择器也能作用在任意元素上（例如把 `body[data-hue="red"][data-mode="light"]` 放宽为 `[data-hue="red"][data-mode="light"]`），卡片自己带 `data-hue` 与 `data-mode`。`data-mode="auto"` 在卡片内要解析为系统当前明暗，不能让卡片卡在默认浅色。
- 键盘：两张卡片做成 `radiogroup`，方向键切换，Enter/Space 选中，焦点环用 `--focus-ring`。

**B. 明暗分段控件（替代「明暗模式」下拉）**

- 三段式 segmented control：`☀ 浅色` ｜ `◐ 跟随系统` ｜ `☾ 深色`，图标 + 文字，当前段有滑动的底色块（动效令牌）。
- 默认选中「跟随系统」。选中「跟随系统」时，下方小字显示系统当前状态，例如"当前系统为深色"（随系统变化实时更新）。

**C. 显示偏好（新增，可选，P1）**

- **界面密度**：舒适 / 紧凑（影响列表行高、内边距，不影响字号下限）。
- **阅读字号**：标准 / 偏大——仅缩放对话区正文（`--fs-body` 一档），UI 控件不动。Agent 产品里用户 80% 的时间在读长回复，这个开关比色相更实用。

### 1.3 反馈方式
- 切换**立即生效**，不需要"保存"按钮，不显示"正在应用外观…""已保存"这类状态行。
- 持久化失败时才提示，文案："外观设置未能保存，下次启动可能恢复默认。"，用 toast，不占页面空间。
- 页面标题区去掉 `appearance-description` 那段说明，换成一句话："选择你喜欢的界面风格。"

### 1.4 验收
- 打开外观页，不读任何文字，就能分辨两个主题并知道哪个是当前的。
- 切到深色，两张缩略图同步变深。
- 页面里没有 `<select>`，没有任何"状态:xxx"文字行。

## 2. 对话区：从"文本框"到"Agent 工作台"

现状：`.message-content { white-space: pre-wrap }`，所有内容当纯文本。这是和"真正的 Agent 桌面端"差距最大的地方。

### 2.1 消息排版
- **Agent 消息不加气泡**，直接排在画布上，左侧小头像 + 作者名；**用户消息保留右对齐气泡**（现有圆角不对称设计保留）。
- 对话列最大宽度 760px 居中，段间距 18–22px。
- 消息 hover 时右上角浮出小工具条：复制 / 重新生成（后者先占位禁用即可）。

### 2.2 Markdown 渲染（不引依赖）
CSP 是 `script-src 'self'`，不要引外部库，也不要用 `innerHTML` 拼用户/模型内容（XSS 面）。用 DOM API 写一个小渲染器，范围限定为：
段落、`#`–`###` 标题、有序/无序列表、粗体、行内 `code`、围栏代码块、链接（只允许 http/https，点击走现有 `openLegalPage` 之类的主进程外开通道，不要在应用内导航）、引用块、表格（可后置到 P2）。
流式输出时，未闭合的围栏代码块要能"边写边显示"，不能整段闪烁重排。

### 2.3 代码块
- 头部条：左侧语言标签（ArkTS / TypeScript / JSON / Shell…，mono，`--fs-caption`），右侧「复制」按钮，点击后文案变「已复制 ✓」，1.5s 恢复。
- 主体：`--font-mono`，13px，行高 1.6，水平滚动，圆角 `--r-control`。
- **代码块底色是新增令牌**（建议 `--code-bg` / `--code-ink` / `--code-line`），4 种外观各配一套：浅色模式用淡灰底，深色模式用比 `--surface` 略深的底；不要在浅色主题里放一块纯黑，那样太突兀。语法高亮可后置，先做到"整洁可读"。

### 2.4 工具调用卡片（替代现在的 `.agent-activity` 一行文字）
每次工具调用一张折叠卡片：
- 收起态一行：状态图标｜工具名（如"读取文件""执行命令""ArkTS 编译"）｜关键参数摘要（mono，截断）｜耗时。
- 状态四种：运行中（旋转环，用 `--accent`）、成功（`--ok` 对勾）、失败（`--danger` 叉）、等待授权（`--warn`）。
- 展开后显示输入/输出，输出区用代码块样式，超长折叠并带「展开全部」。
- 同一轮里连续多个工具调用**合并成一组**，组头显示"执行了 N 个步骤"，默认折叠，进行中的那个保持展开。

### 2.5 其他状态
- **思考过程**：折叠块"思考中…/已思考 8 秒"，默认收起，文字用 `--ink-muted`。
- **流式光标**：回复生成中末尾一个细竖线闪烁（`--accent`），结束消失。
- **回到底部按钮**：用户上滑查看历史时，右下角出现圆形箭头按钮，点击平滑滚到底，带"有新内容"小圆点。
- **错误消息**：左侧 `--danger` 竖条 + 浅 `--danger-wash` 底，附"重试"按钮，而不只是把文字变红。

## 3. 欢迎页与空状态

现状：三张静态建议卡 + 一句标语。

- 欢迎页顶部加**工程摘要行**：工程名｜SDK 版本｜Agent 已连接状态点。环境检测的数据已经有，直接复用。
- 建议卡改为**根据上下文变化**：未选工程时第一张是「选择一个 HarmonyOS 工程」（主按钮样式）；已选工程后才显示"了解结构 / 排查编译错误 / 检查运行效果"。
- 下方新增「最近会话」最多 3 条（标题 + 相对时间），点击恢复。无会话时整块不渲染，不放"暂无数据"。
- 所有空状态（无项目、无会话、无模型）统一一套**插画式空态**：用 `--accent-wash` 圆底 + 线性图标 + 一句话 + 一个主动作，不要只有灰色小字。

## 4. 侧栏

- **会话条目状态点**：运行中（`--accent` 脉冲）、已完成（无点）、出错（`--danger`）、等待授权（`--warn`）。一眼看出哪个在跑。
- 会话按项目分组可折叠；hover 时右侧出现「重命名/删除」图标，而不是常驻。
- **折叠态改为图标栏（约 56px）**，而不是完全隐藏。图标栏顶部是品牌标、中部是新建/搜索/设置，悬浮出 tooltip（含快捷键）。展开/折叠宽度用动效令牌过渡。
- 底部连接卡片保留，但文案精简：状态点 + "已连接 · DevEco Code 0.2.3"，一行完成。

## 5. 输入区

- 输入框随内容自动增高到上限（约 8 行）再滚动。
- **三种状态**：空闲 / 生成中（发送键变停止键，输入框仍可输入但发送被禁用并提示"Agent 正在工作"）/ 未连接（整体半透明 + 引导文案 + 主动作"选择工程"）。
- 上下文区做成**可移除的 chip 行**（工程、已添加文件），chip 有 hover 态和 × 。
- 底部加一行低调的提示：`Enter 发送 · Shift+Enter 换行`，mono 的 kbd 样式，`--ink-muted`。
- 模型 / 思考强度选择器保持现有位置，但把 Provider 小标识的底色改为取自该 Provider 的品牌色（见 §6），不再统一一个色。

## 6. Provider 与模型（v1 要求的「热门 + 一个自定义入口」仍未落地，本轮必须做）

### 6.1 Provider 管理页
- 默认只显示以下精选 Provider（按此顺序，已连接的置顶，未连接的在后）：
  **DevEco 内置**（固定第一）／Anthropic／OpenAI／Google Gemini／DeepSeek／阿里通义（Qwen）／智谱 GLM／月之暗面 Kimi／硅基流动 SiliconFlow
- 精选列表用**稳定的 provider id 白名单**匹配核心返回的 `providers.all`，白名单里没返回的直接不显示；不要硬编码"应该有"。
- 紧接其下**只有一个入口**：「添加自定义 Provider」（OpenAI 兼容），沿用现有表单，但做两处改进：Provider ID 由显示名称自动生成（用户可改）；端点填完后自动补全 `/v1` 的提示。
- 其余几百个 Provider 收进一个折叠区「更多 Provider」，带搜索框，默认收起。
- 每行布局：品牌色圆角方标（首字母单色块，每个 Provider 一个固定品牌色，已在 `design-preview` 里给出一套）｜名称 + 状态（已连接 ● / 未配置）｜右侧**最多 1 个主按钮**（未配置→「配置」，已配置→「管理」）。其余操作（替换 Key、移除凭据、编辑）收进行内的「⋯」菜单，**不要一行摆 5 个按钮**。

### 6.2 模型选择浮层
- 分组：**常用**（用户最近用过的 3 个）→ 按 Provider 分组。
- 每个模型一行：模型显示名｜能力小标签（推理 / 长上下文 / 视觉，仅在核心元数据里有才显示，没有就不显示，不要编）｜右侧上下文长度（mono，如 `200K`）。
- 模型 ID（`provider/model`）改为 hover 才显示的次要信息，默认行里不展示，降低噪音。
- 浮层底部的「保存为默认」去掉 `<select>`，改成一个小的分段控件「全局 / 当前工程」+ 按钮。

## 7. 设置弹窗结构

- 导航分组加小标题与图标：
  - **通用**：外观
  - **账号**：账号与开发者、协议与隐私
  - **模型**：Provider、配置中心
  - **系统**：环境与诊断
- **「首次设置」不应是一个设置分类。** 它是引导流程：首次启动全屏展示（5 步进度，完成后不再出现），之后从设置里移除；需要时可在「环境与诊断」里提供"重新运行向导"。
- 弹窗尺寸固定偏大（约 920×640），打开时轻微缩放淡入；导航项选中态用 `--accent-wash` 底 + 左侧 3px `--accent` 竖条。
- 顶部加设置搜索框（P2）。

## 8. 动效与细节令牌

新增（`:root`，主题无关）：

| 令牌 | 建议值 | 用途 |
|---|---|---|
| `--motion-fast` | 120ms | hover、按下、颜色变化 |
| `--motion-base` | 200ms | 面板展开、分段控件滑块、浮层出现 |
| `--motion-slow` | 320ms | 侧栏折叠、弹窗进出 |
| `--ease-out` | cubic-bezier(.2,.8,.2,1) | 默认缓动 |
| `--r-card` / `--r-control` / `--r-chip` | 16 / 12 / 8px | 圆角（v1 预览稿已定，若未成令牌请补上） |

- 全局 `@media (prefers-reduced-motion: reduce)` 把上述时长置为 0.01ms，并关闭脉冲/旋转/流光（含现有 `.effort-particle` 流星动画）。
- 深色模式**层级靠表面明度区分，不靠阴影**：弹层/卡片比画布更亮一档，阴影只做极淡的辅助。
- 文本选中色用 `--accent-wash` 底；滚动条细、圆角、颜色取自令牌，hover 时加深。
- 加载用骨架屏（`--surface-raised` 微光扫过）代替"读取中…"文字。

## 9. 桌面端质感（真正区别于"网页"的部分）

1. **窗口标题栏跟随主题。** 若使用自定义标题栏/`titleBarOverlay`，其颜色必须随 `--canvas`/`--ink` 切换；这需要渲染进程在主题变化时通知主进程更新（新增一个 IPC，如 `theme:apply-chrome`，后端工作可由负责主进程的同学接，渲染侧先按接口形状调用）。同时更新 `<meta name="theme-color">`（v1 已做）。
2. **窗口最小尺寸**与响应式：低于约 900px 宽时侧栏自动收为图标栏，而不是挤压主区。
3. **快捷键层**：`Ctrl+N` 新建、`Ctrl+K` 搜索（已有）、`Ctrl+,` 打开设置、`Ctrl+B` 切换侧栏、`Esc` 关浮层；设置里放一张快捷键速查（P2）。
4. **底部状态条**（可选 P2）：窗口最底一条细条，左：连接状态点；中：当前工程路径（mono，中间截断）；右：模型名 + 上下文用量小进度条。这是 IDE 类桌面应用的典型形态，能立刻提升"专业工具"感。

## 10. 优先级与验收

| 级别 | 内容 |
|---|---|
| **P0** | §1 外观页重做；§6.1 Provider 精选+自定义+行内菜单；§2.1–2.3 消息排版 / Markdown / 代码块；§0 文案去实现化 |
| **P1** | §2.4 工具调用卡片与思考块；§3 欢迎页上下文化；§4 会话状态点与图标栏；§5 输入区三态；§6.2 模型浮层；§8 动效令牌；§7 首次设置拆为引导 |
| **P2** | §1.2-C 显示偏好；§9 标题栏跟随主题 / 状态条 / 快捷键；设置搜索；表格渲染；语法高亮 |

**交付验收（Luna 自测后附截图）：**
1. 4 种外观 × {外观页、有代码块的对话、Provider 页、模型浮层} 共 16 张截图。
2. 全文搜索：`styles.css` 在 `:root`/主题块之外无字面色值；无小于 11px 的字号；无新增 `<select>` 用于外观或"作用域"切换。
3. 键盘可完成：切换主题卡片、切换明暗、复制代码块、展开工具卡片。
4. 开启系统"减少动态效果"后，无脉冲/旋转/流光。
5. 界面任何位置搜不到：`IPC`、`配置文件`、`页面运行期间`、`暂存`。
